# iOS utility app roadmap

Updated 2026-11-23. Apple's release page was rechecked today: iOS 27.2.1 remains the newest public release, iOS 27.3 beta 2 v2 remains the newest listed beta, and Xcode 27.2 is the newest stable Xcode. This is a build roadmap for locally built apps and prototypes. It does not authorize installation on a phone, release, publication, deployment, or cloud builds.

## Portfolio goal

Build the focused utility apps and app features below into complete, locally
buildable iPhone apps or app features, then keep a ranked list of adjacent apps
to build.
Each product needs its core workflow, local data handling, honest capability
gates, a repeatable Mac build command, and a status record. Do not install to an
iPhone, publish, deploy, or trigger a cloud build as part of this goal. The
existing active Codex goal tracks this work.

Completion means every product has a usable core flow, a local build that
compiles against its intended SDK gates, documented setup and privacy behavior,
and an ordered next-step list. Runtime validation that requires an iPhone stays
out of scope; report it as a separate open item.

## Platform baseline

- Apple's newest public iPhone release is iOS 27.2.1 (November 9, 2026); the newest beta listed is iOS 27.3 beta 2 v2 (November 19, 2026). Xcode 27.2 is the latest stable release and Xcode 27.3 beta 2 is the latest Xcode beta listed (November 16). Xcode 27.2 includes Swift 6.4 and the iOS 27.2 SDK and requires macOS 26.6 or later; this Mac is running macOS 26.6.1. Xcode 27.2 is installed here, replacing Xcode 26.0.1. Its first-use license has not been accepted, so `xcodebuild -showsdks` currently stops before exposing the SDK list. iOS 27-only compile verification remains pending that setup step. Do not describe an iOS 27 capability as implemented based on a web page or a Mac-only API experiment.
- Vision already provides local OCR, image categorization, visual similarity, and video analysis on earlier supported iOS versions. The Screenshot Scout app uses the system photo picker and Vision; selected image bytes and extracted metadata stay in its app container.
- iOS 27 Foundation Models supports image attachments in prompts. The model must be available and support image input; use the user's selected local image and keep generated descriptions reviewable. Apple documents no built-in video input, so video analysis remains frame-based. User-selected pickers or a system share action are the boundary for screenshots and conversations; EverReach's Share extension now accepts one shared image into a local App Group inbox, and the app waits for the user to open and review it.
- Siri AI app integration is currently a Developer Preview in iOS 27.3 beta, using App Intents. It is not part of public iOS 27.2.1. Apple says the preview requires an Apple Intelligence-enabled device in a supported language, has region and age restrictions, and that further terms and usage policies are forthcoming; some server-backed Apple Intelligence features also have daily limits. Keep existing App Intents as the stable interaction path and treat Siri AI integration as optional beta exploration.
- Music Understanding analyzes an audio asset supplied by the user or app, on-device, across rhythm, key, structure, pace, instrument activity, and loudness. Apple currently marks the framework documentation as beta. Start with files the user chooses; do not promise access to protected streaming catalog audio.
- Media Device and AVSystemRouting require iOS 27 and are documented for streaming from an iPhone to remote playback hardware. Both the extension and container app require the media-device-extension entitlement. Apple's current guide describes real-time samples being delivered through the extension to that device; it does not document a same-iPhone return path for DSP or unrestricted capture from every app. The Developer Program Agreement defines a Media Device Extension as sending content from the iPhone or iPad to another device and says the app bundling the extension should have the sole purpose of delivering and installing it. This appears materially at odds with putting a same-phone EQ route inside Sonance EQ. Keep Route Lab isolated and do not productize this path without written Apple guidance on both same-device processing and the container app's purpose.

## Ordered product work

| Order | App / product | Form | Build boundary and next milestone |
|---|---|---|---|
| 1 | Sonance EQ for iPhone | Standalone app plus AUv3 | Existing prototype plays user-selected files with parametric EQ, built-in presets, A/B, live meters, output correction, speech modes, and Siri/Shortcuts actions to enable or disable bypass. Everyday Workout, Focus, and Late Night curves use calculated peak-response headroom and disable bypass when applied. A preference-guided headphone profile assistant creates editable curves, previews the response and preamp headroom, saves profiles to presets, and can apply a suggestion for A/B comparison. Keep improving this on stable APIs. Keep cross-app route support out of Sonance EQ; public docs target remote hardware and the agreement says the app bundling it should exist solely to deliver and install the extension. Require written Apple guidance before resuming same-phone product work. |
| 2 | Screenshot Scout / Creator Library | Standalone utility | Index user-selected images and videos with local OCR, Vision labels, exact duplicate detection backed by in-memory SHA-256 sets rebuilt from JSON indexes, stoppable multi-image imports, cancellable visual-similarity ranking for images, multi-term search across OCR/scene descriptions/labels, search across five sampled video frames with matching timestamps shown in results, user-controlled JSON inventory export, and a persistent review queue. It reapplies backup-exclusion hints to the local library, media and index files, and rolls back an image copy if indexing fails. Optional iOS 27 Foundation Models descriptions cover an image or one sampled video frame at a time, preserve edits during generation, and require review before saving. Compile the new model paths with Xcode 27 and review them on a supported runtime. |
| 3 | EverReach Capture | Feature in EverReach | The in-app picker and one-image Share extension both feed the screenshot review flow. The Goal Picker also opens that review flow directly in LOCAL_ONLY iOS builds; Apple Vision extraction and contact-note saves stay on device, while follow-up drafting and image attachment require connected mode. The extension writes one pending image to a backup-excluded App Group inbox, then asks the user to open EverReach manually; the app routes to review after authentication and onboarding. Local Vision OCR can suggest up to five explicit full-name contact matches, ordered by the first mention in OCR with a stable alphabetical tie-break; selecting a match only changes the review target. Editable notes, optional screenshot attachment, and separate follow-up drafting remain explicit user actions. Switching/removing the selected image or leaving capture invalidates in-flight analysis and note drafting; a suggestion is also discarded if the user edits the note or OCR source while generation is running. Native App Shortcuts open capture or prefill the authenticated People search with a contact name; contact notes remain in EverReach and search text is excluded from analytics. ESLint and the Expo iOS JavaScript export passed on 2026-11-23, including ordered multiple-match and local-only capture flows; native extension, App Group, and iOS 27 model compilation remain Xcode-license-gated, with runtime flow pending. |
| 4 | Sonance Voice and Headphone Profiles | Sonance EQ modes | Keep dialogue, podcast, audiobook, headphone, sleep, focus, speaker, and A/B profiles within the EQ product while they use the same playback and DSP engine. A listening-preference assistant now makes a moderate editable EQ starting point without claiming headphone measurement or model correction. A 15–90 minute sleep timer is part of the player prototype. Split only if customer evidence supports a distinct app. |
| 5 | Track Study (music practice and library organizer) | Standalone app | Locally buildable iOS 17+ app imports multiple user-selected audio files in a stoppable batch into a private library, migrates the prior single-track record, excludes each file and the index from device backups, and leaves existing records intact if a file import fails. Users search by title, all analyzed key spans, tempo, instrument labels, pace values, and marker or loop name; multiple terms can match across fields, result rows show up to two matching metadata labels, and the library count reflects the filtered set. Tracks sort by title or import date, with optional earliest-key/tempo sorting after analysis. Each selected track retains its practice markers, A/B repeat loops, and analysis. It supports seeking and pitch-preserving 0.5×–1× practice speed, plus a user-initiated text plan export that never attaches audio. Music analysis can be canceled; changing tracks, removing a track, or leaving the app discards stale results. When analysis is available, detected section, key, pace, and first instrument spans can jump the playhead to a practice point; detected keys display standard note symbols such as D♭ and F♯. Pace is labeled as perceived events/minute, separately from BPM, and integrated/peak loudness are shown. Siri/Shortcuts can mark the current playhead. The iOS 27 Music Understanding path requests all six documented dimensions. Compile and review this beta API before relying on its results. |
| 6 | Clear Record (Meeting Notes) | Standalone local utility | iOS 17 prototype records after explicit consent, stores audio and notes locally, marks its folder, recordings, and index for backup exclusion, stops on interruption/background, and provides foreground-only playback with seeking, 15-second skips, and saved pitch-preserving speed choices from 0.75× to 2×. Its private session list searches titles, transcript text, and saved summaries locally; all whitespace-separated query words can match across different fields, and transcript or summary hits show labeled excerpts. Playback pauses on interruption and stops on app backgrounding, recording, transcription, or leaving the detail screen. The app lists system-supported on-device speech locales and lets the user correct transcripts. Siri/Shortcuts can transcribe the newest saved recording using on-device Speech checks. On iOS 27, a foreground summary shortcut can prepare a local draft, return only a neutral status to Siri, and open an editable in-app review sheet; the draft is not saved until the user taps Save. A user-initiated combined text export includes the saved transcript and summary, labels a stale summary, and excludes audio. The optional iOS 27 Foundation Models path supports up to 120,000 transcript characters with local section summaries and successive consolidation, preserves transcript-to-summary provenance, and keeps summary actions unavailable during active edits. Playback, backup-exclusion metadata, and the iOS 27 model path need compilation with Xcode 27; then review long-transcript outputs on a supported runtime. Do not promise call capture, arbitrary background recording, or network transcription. |

## Product boundaries

The named products above are intentionally fewer than the idea list: Voice, headphone tuning, sleep, focus, speaker tuning, and A/B comparison share Sonance's DSP and profiles; screenshot organization and creator media cleanup share one user-selected media index; contact capture belongs in EverReach. This keeps separate apps for distinct jobs and keeps related controls together.

## Build sequence

1. Keep Sonance EQ as the first product and continue its standalone file-player and AUv3 experience.
2. Continue Screenshot Scout on stable PhotosUI and Vision APIs; compile its gated iOS 27 image-description path with Xcode 27 when available, then refine search and indexing for larger libraries. The persistent user-reviewed candidate queue is implemented locally.
3. Clear Record now has foreground-only local playback controls, alongside its long transcript summaries through local sectioning and multi-pass consolidation. Compile the player and iOS 27 path with Xcode 27 when available, review section boundary behavior and stale-transcript handling, and validate dynamic locale support and recording behavior on-device when that is back in scope.
4. EverReach's Expo iOS JavaScript export now passes locally. Once Xcode is usable, compile the Share extension, App Group entitlements, App Intents, and Foundation Models paths, then verify share handoff, deep-link delivery, and model output when a supported runtime is available; runtime and output review remain pending.
5. Track Study now has a persistent multi-track file library, title/date sorting, optional analyzed key/tempo sorting, per-track practice data, saved A/B loops, pitch-preserving slow playback, and cancellable analysis. Compile the optional Music Understanding analyzer with Xcode 27 when the installed SDK is usable; then review its beta API outputs and library migrations.
6. Keep Media Device out of Sonance EQ pending written Apple guidance: public documentation targets remote playback hardware, and the agreement says the app bundling it should exist solely to deliver and install it. A third-party same-phone demo is not evidence of Apple's approval. Physical iPhone installation is outside the current goal.
7. Continue Sonance's guided headphone profile work on stable APIs; refine preset naming, accessibility, and comparison behavior before considering a standalone sound-profile app.
