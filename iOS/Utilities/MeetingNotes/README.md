# Clear Record (Meeting Notes)

Clear Record is a local meeting recorder and note organizer prototype for iPhone and iPad (iOS 17+). A person must confirm that everyone present has agreed before each recording. Recording state remains visible, and a Stop control is always available. Recording stops and saves when the app leaves the foreground or the audio session is interrupted. Audio and transcripts stay in the app's Application Support folder unless the user explicitly shares the audio or transcript. The app marks its folder, audio recordings, and session index for device-backup exclusion; Apple describes this as guidance to the backup system, not an absolute guarantee. Export recordings or notes separately when you want a portable copy. Saved recordings can be replayed in the detail screen with seeking, 15-second skips, and saved playback speeds from 0.75× to 2×. Apple documents the supported rate range as pitch-preserving. Playback pauses on audio interruption and stops when the app leaves the foreground; background playback is not enabled.

Transcription is a separate action after recording. The app lists locales returned by Apple's Speech framework only when that locale's recognizer reports `supportsOnDeviceRecognition`. It checks service availability again when transcription starts, requests Speech permission at that point, and sets `requiresOnDeviceRecognition`; it will not fall back to network recognition. Locale support varies by device and system configuration. If the selected language or service is unavailable, the recording remains saved and the app reports the condition.

The app does not record calls, read other apps, start in the background, or upload media. A Siri/Shortcuts action can transcribe the newest saved recording with on-device Speech, but will not overwrite an existing transcript. On iOS 27, a separate optional Foundation Models action can draft a concise summary, decisions, action items, and open questions from the newest saved transcript. The shortcut opens Clear Record, returns only a neutral status to Siri/Shortcuts, and stages its text in memory for review; it does not speak or return the summary text and does not save it automatically. The on-device model must be available; its draft is editable, remains unsaved until the user reviews and saves it, and is marked stale if the transcript later changes. Transcripts up to 120,000 characters are split into 6,000-character sections, summarized locally, and consolidated in successive passes; long summaries can lose details between sections, so review the saved transcript and draft before sharing. The person can cancel a long draft, and leaving the detail screen cancels any active draft. Summary generation is disabled while transcript or summary edits are in progress. No summary is generated automatically. The app supports transcript correction and local saving, rename, sharing the transcript or saved summary separately, and a combined user-initiated text export that flags a stale summary and never attaches audio. Audio can also be shared separately by explicit action. The app supports explicit deletion of the local recording and note. Speech permission is requested only when the person chooses to transcribe a saved recording or invokes the shortcut; recording itself requires microphone access and participant consent.

Foundation Models support is compile-gated for Swift 6.4 / Xcode 27 and iOS 27. The last verified local build used Xcode 26.0.1 and compiled the established recording and transcript experience with the summary action unavailable. Xcode 27.2 is now installed, but its first-use license has not been accepted, so the iOS 27 model path and new summary shortcut have not yet been compiled or reviewed at runtime. Apple describes `respond(to:)` as asynchronous and requires checking on-device model availability before use. The summary shortcut uses App Intents foreground execution and a status dialog without returning the private summary as an intent value. See [Foundation Models generation](https://developer.apple.com/documentation/foundationmodels/generating-content-and-performing-tasks-with-foundation-models), [SystemLanguageModel availability](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel), and [App Intents](https://developer.apple.com/documentation/appintents/app-intents).

Build locally with XcodeGen and Xcode:

```sh
xcodegen generate --spec iOS/Utilities/MeetingNotes/project.yml --project iOS/Utilities/MeetingNotes
xcodebuild -project iOS/Utilities/MeetingNotes/MeetingNotes.xcodeproj -scheme MeetingNotes -destination 'generic/platform=iOS Simulator' -jobs 1 CODE_SIGNING_ALLOWED=NO build
```

The last simulator-target build, before local playback was added, succeeded with Xcode 26.0.1 on 2026-11-22. Xcode 27.2 is installed, but its first-use license remains unaccepted, so the playback and backup-exclusion changes and iOS 27 model path have not yet been compiled. No runtime exercise, phone installation, or release is part of this project. Apple documents AVAudioPlayer file playback, seeking through `currentTime`, playback-rate controls, explicit interruption handling, and backup exclusion in [AVAudioPlayer](https://developer.apple.com/documentation/avfaudio/avaudioplayer), [currentTime](https://developer.apple.com/documentation/avfaudio/avaudioplayer/currenttime), [enableRate](https://developer.apple.com/documentation/avfaudio/avaudioplayer/enablerate), [rate](https://developer.apple.com/documentation/avfaudio/avaudioplayer/rate), [Handling audio interruptions](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions), and [Optimizing your app’s data for iCloud Backup](https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup).
