# Track Study

Track Study is a local iPhone and iPad music library and practice utility (iOS 17+). It imports multiple audio files selected in the system file picker into a private Application Support library. Batch imports run one file at a time, can be stopped after the current file, and report partial success if individual files fail. Users can search by title, analyzed key or tempo, Music Understanding instrument or pace, and saved marker or loop name. Multiple query terms can combine across those fields, so a key and tempo can be searched together; result rows show up to two matching metadata labels. The library count reflects the active search. Tracks sort by title or import date; after on-device analysis, first detected key and tempo become additional sort choices. Selecting a track opens its local player and keeps that track's practice markers, A/B repeat loops, and analysis together. The saved library migrates the previous single-track record on first launch. Practice playback offers 0.5×, 0.75×, 0.9×, and 1× speed; the spectral pitch algorithm keeps the source pitch steady as playback slows, though very slow audio can sound less natural. The selected speed is saved on the device. A loop repeats a saved passage during playback; users set A and B from the current playhead and can remove loops independently. A user-initiated system share action exports the title, markers, repeat ranges, and available analysis as text; it never attaches the audio file. A Siri/Shortcuts action can mark the current playhead without interrupting practice. Removing a track is an explicit action that deletes only that imported file and its local marker, loop, and analysis record. The app marks its storage directories, each imported audio file, and the library index for device-backup exclusion, and reapplies the file hint after atomic index writes and when reopening the library. Apple describes the setting as guidance to the backup system, not an absolute guarantee. A failed import removes its partial copy and does not change existing library records.

The iOS 27 Music Understanding integration is gated for the Swift 6.4 compiler in Xcode 27 and iOS 27. With that SDK and a supported runtime, it requests rhythm, key, song structure, pace, instrument activity, and loudness from the user-selected local asset and stores the summary with that track. Detected key names use readable note symbols such as D♭ and F♯. Analysis can be canceled; leaving Track Study or removing the imported track cancels the active session, and a late result is discarded if its track is no longer selected. Apple currently marks the framework documentation as beta, so these results are an optional aid until compiled and reviewed on a supported runtime. The app labels pace as perceived events per minute, separately from BPM; section, key, pace, and first detected instrument spans can jump playback to the corresponding start time. Integrated loudness and peak level are shown when available. The last verified build used Xcode 26.0.1 / iOS 26 SDK and compiled playback and practice features while leaving the analyzer disabled. Xcode 27.2 is now installed, but its first-use license has not been accepted, so the new analyzer path has not been compiled locally.

The app does not read Apple Music or other apps' protected streaming audio, access a user's broader media library, send audio to a service, record microphone input, or publish results. Its saved app data is excluded from device backups. Framework output is analysis guidance, not a guarantee of correct musical interpretation.

The App Shortcut “Mark this point in Track Study” requires a saved track, stores a `Siri marker` at the current playhead, and does not start or record audio. It is registered through Apple's App Intents framework and is available from Siri, Spotlight, and Shortcuts when supported by the OS.

Generate and build locally with XcodeGen and Xcode:

```sh
xcodegen generate --spec iOS/Utilities/TrackStudy/project.yml --project iOS/Utilities/TrackStudy
xcodebuild -project iOS/Utilities/TrackStudy/TrackStudy.xcodeproj -scheme TrackStudy -destination 'generic/platform=iOS Simulator' -jobs 1 CODE_SIGNING_ALLOWED=NO build
```

The last iOS Simulator target build, with practice loops, succeeded with Xcode 26.0.1 on 2026-11-22. The resulting bundle identifier is `com.isaiahdupree.trackstudy` and contains arm64 and x86_64 simulator executables. No simulator runtime exercise, iPhone installation, or release is included in this build task.
